### Problem

Phase-0 branch protection requires only `checks` + `tests`. Once coverage (SB-3), knip
(SB-4) and e2e (SB-5) are live and stable, the gate should require them — and the
rail-protected paths (loop-protocol §6 R2) should be human-owned via CODEOWNERS so no
write to them merges without explicit human review, regardless of labels.

### Bet

If the required-check set becomes {checks, tests, coverage, knip, e2e} and CODEOWNERS
covers the R2 path list, then no PR merges with any gate red and no harness-path change
merges without the operator, verifiable by the repo settings API and a test PR.

### Success criteria

- [ ] `.github/CODEOWNERS` added: `ops/yantra/`, `.github/`, `.brain/` (except inbox), `LICENSE`, `apps/yantra/` → repo owner.
- [ ] PR body contains the exact branch-protection settings for the operator to click (required checks list, 0 approvals for unprotected paths, CODEOWNERS review required) — the agent may NOT change repo settings itself; this PR ships files + instructions only.
- [ ] Blast-radius section in PR body: what breaks if this is wrong, and the rollback (delete CODEOWNERS, restore 2-check list).
- [ ] All of: `yarn lint`, `yarn check-types`, `yarn test:run` green in CI.

### Out of scope

Changing rails in grade.sh (harness is frozen to the loop), auto-merge widening.

### Evaluation

After operator applies settings: a scratch PR with a red knip check is unmergeable; a PR touching ops/yantra/ demands owner review. Revert condition: required checks block unrelated work due to flake — operator loosens to previous set.
