### Problem

The shared skill-library (D9) has no home. The HUMAN must first create the private
`yantra-skills` repo (empty, README-only); this task then PRs the structure into it:
layout, entry format, and the promotion contract, so SB-18's seeding has rails.

### Bet

If the skills repo has a defined layout and entry contract, seeded skills (SB-18) land
uniform and promotable, verifiable by the structure files existing and passing the
format's own linter-by-example.

### Success criteria

- [ ] PRECONDITION (human, blocks claim): `yantra-skills` private repo exists; `YANTRA_SKILLS_REPO` added to the VPS env file.
- [ ] PR to yantra-skills: `README.md` (what belongs here, what doesn't — portable craft only, no project/user specifics), `skills/` layout `skills/<stack-tag>/<skill-name>.md`.
- [ ] Entry template: frontmatter (stack tags, source URL, proven-count, added-by run ULID) + body ≤ 80 lines + "when NOT to use".
- [ ] Promotion contract documented: entries only via PR; proven-count incremented only by dream citing ≥ 2 independent runs (loop-protocol §2.5).
- [ ] One example skill included demonstrating the format (can be Yantra-meta: "writing executable success criteria").
