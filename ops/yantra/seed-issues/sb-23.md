### Problem

The operator budget is 1–2 h/day (D13). Without a fixed morning routine, loop
supervision degrades into ad-hoc poking — or worse, gets skipped. The routine's inputs
(telemetry, parked issues, kill switch, AoE, Novu digests) all exist by now; they need
one checklist.

### Bet

If DAILY.md scripts the 10-minute morning check, the operator catches every parked
issue and anomaly in one pass, verifiable by dry-running the checklist end-to-end.

### Success criteria

- [ ] `ops/yantra/DAILY.md`: copy-pasteable command per check — telemetry tail (`tail -50 /opt/yantra/telemetry/loop.log`, jq one-liners over runs.jsonl for yesterday's outcomes), parked issues (`gh issue list --label needs-human --label agent:failed`), kill-switch state, R3 ledger, disk/RAM (`df -h`, `free -h`), AoE session glance, review-queue check.
- [ ] Ends with the two decision points: what to re-ready (fix + `spec:ready`), what to escalate/close.
- [ ] Every command runs as-is on the VPS (paths match ops/yantra reality — verify each against the scripts, don't invent flags).
- [ ] `docs/yantra/OPERATORS.md` (SB-2) updated: "coming in SB-23" note replaced by a link.
- [ ] All of: `yarn lint`, `yarn check-types`, `yarn test:run` green in CI.

### Out of scope

New tooling/dashboards (Phase 3 scorecards), harness changes.

### Evaluation

Operator runs it two consecutive mornings ≤ 10 min each (honest self-report — the Phase-1 exit test #5). Revert condition: none (docs-only).
