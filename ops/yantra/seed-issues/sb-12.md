### Problem

After SB-11, journal references survive inside the worker layer: `data.worker.ts`,
`sync/sync.orchestrator.ts`, `db/db.manager.ts`, `db/files.db.ts`, `db/team_data.wipe.ts`
mention journal tables/stores. D16 requires the worker/sync/Dexie INFRA itself to
survive — this task removes the journal-DOMAIN tables/handlers from it without touching
the sync mechanics.

### Bet

If we remove journal tables/handlers from the worker layer while leaving the sync
engine's structure intact, sync tests and E2E stay green and the frontend greps go to
zero, verifiable by CI + greps below.

### Success criteria

- [ ] Journal-domain Dexie tables, sync handlers, and wipe entries removed from `apps/frontend/src/worker/**` and `apps/frontend/src/sw/**`.
- [ ] The sync engine's generic mechanism (orchestrator, SSE handling, delta application, DataWorker/MediaWorker split) is structurally unchanged — PR body must include a "what I did NOT touch" section naming these files/functions.
- [ ] `grep -ri "journal" apps/frontend/src --include="*.ts" --include="*.tsx"` → 0 hits.
- [ ] Dexie schema version bumped correctly if tables are dropped (document the upgrade path in the PR body).
- [ ] All of: `yarn lint`, `yarn check-types`, `yarn test:run` green in CI; `yarn test:e2e:with-build` green locally (tail in PR body).

### Out of scope

zod-schemas (#13), backend, any change to sync transport/SSE logic.

### Evaluation

Post-merge canary green; E2E green. Revert condition: any sync/offline E2E regression.
