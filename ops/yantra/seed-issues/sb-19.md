### Problem

Advise and execute prompts don't yet include matched skills — the library exists
(#17/#18) but no turn reads it. Loop-protocol §2.2 specifies matching by the spec's
`stack:` tags. This is a harness change (`ops/yantra/`), therefore T3 and human-merged.

### Bet

If advise.sh/execute.sh clone yantra-skills and inline entries whose stack tags
intersect the spec's `stack:` field, agents start their turn holding relevant craft,
verifiable by the assembled prompt (logged run) containing the matched skill bodies.

### Success criteria

- [ ] `advise.sh` + `execute.sh`: fetch `$YANTRA_SKILLS_REPO` (shallow, cached ≤ 1 h), match `skills/<tag>/*.md` where `<tag>` ∈ spec's `stack:` list, inline at most 3 matched skills (shortest-first) into the prompt.
- [ ] Missing/empty skills repo degrades gracefully (log + continue — current behavior preserved).
- [ ] `prompts/advise.md` + `prompts/execute.md` bumped to `prompt-version: 2` (telemetry will correlate outcomes to the change — the A/B is the version field).
- [ ] Dry-run test: fixture spec with `stack: bash` + a fixture skill → assembled prompt contains the skill body (add to the ops/yantra dry-run doc).
- [ ] All of: `yarn lint`, `yarn check-types`, `yarn test:run` green in CI.

### Out of scope

Skill auto-promotion changes, routing changes, matching smarter than tag-intersection (Phase 3 scorecards decide if it's worth it).

### Evaluation

Telemetry: compare grade first-try pass rate for prompt_version 2 vs 1 over the following week. Revert condition: pass rate drops ≥ 15 points — revert to version 1.
