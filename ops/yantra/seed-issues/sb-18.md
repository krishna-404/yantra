### Problem

An empty skill-library helps nobody; writing every skill from scratch wastes the
adopt-and-compose leverage. Curated external collections (mattpocock/skills,
addyosmani/agent-skills, Forward Future loop-library) contain proven craft worth
seeding — rewritten to our format, never dumped verbatim.

### Bet

If we seed 8–12 curated, rewritten skills tagged by our actual stack, advise/execute
prompts (once #19 wires matching) get relevant craft at spawn, verifiable by each entry
passing the #17 format and tagging rules.

### Success criteria

- [ ] 8–12 entries in `yantra-skills` via ONE PR, each: rewritten (not copied) to the #17 template, ≤ 80 lines, source-linked, stack-tagged from our real stack (node, orchid, orpc, react, vite, dexie, github-actions, bash, postgres).
- [ ] Selection bias toward what the Phase-1 backlog needs: safe module deletion, migration discipline, CI hardening, test-first bugfixing, PR hygiene.
- [ ] Each entry has a "when NOT to use" section (negative knowledge is part of the craft).
- [ ] proven-count starts at 0 for all (nothing is proven until telemetry says so).
- [ ] No verbatim dumps: PR body links each source next to a one-line "what changed in rewrite".

### Out of scope

Prompt wiring (#19), skills beyond 12 (quality over volume), loop-library `loopy` API integration (Phase 3+).

### Evaluation

After #19: matched skills appear in advise/execute prompts for stack-matching issues. Revert condition: none (content-only).
