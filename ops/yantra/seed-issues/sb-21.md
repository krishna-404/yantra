### Problem

The operator has no live view into running agent sessions (D4: AoE is the cockpit —
TUI + mobile web dashboard — it never drives the loop). Tonight's loop is observable
only via `loop.log` and GitHub. Interventions (attach, inspect a stuck execute run)
need a session-level surface.

### Bet

If AoE runs on the VPS and the loop's container sessions are visible in it, the
operator can inspect/attach from a phone, verifiable by the doc's own checklist.

### Success criteria

- [ ] This PR ships docs + any glue config ONLY (the agent cannot install on the VPS): `ops/yantra/AOE.md` with exact install commands, how the loop's `docker run` sessions surface in AoE, phone-attach steps, and a "what AoE must NEVER do" section (it never drives the loop — D4).
- [ ] Glue (if needed): a labeled naming convention for exec containers (e.g. `--name yantra-run-<ULID>`) added to execute.sh is OUT of this PR (harness = T3); instead the doc specifies the desired convention for a follow-up T3 issue if required.
- [ ] Checklist in the doc the operator ticks post-install: AoE up · loop session visible · phone attach works.
- [ ] All of: `yarn lint`, `yarn check-types`, `yarn test:run` green in CI.
