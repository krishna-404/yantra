### Problem

Loop PRs carry a structured body (summary, spec-criteria checklist with evidence,
self-check tail — per `ops/yantra/prompts/execute.md`). Human-authored PRs carry
whatever the author felt like, so the grader and reviewers get inconsistent input.

### Bet

If `.github/pull_request_template.md` mirrors the execute agent's required structure,
human PRs arrive gradeable in the same shape, verifiable by opening any new PR and
seeing the template.

### Success criteria

- [ ] `.github/pull_request_template.md` exists with sections: Summary · Spec criteria (criterion → how satisfied → evidence pointer) · Test evidence · Notes/justified additions.
- [ ] Content matches the deliverable format in `ops/yantra/prompts/execute.md` (same section names, so rubrics apply uniformly).
- [ ] Diff touches ONLY the new template file, ≤ 40 lines.
- [ ] All of: `yarn lint`, `yarn check-types`, `yarn test:run` green in CI.

### Out of scope

Issue templates (exists), CODEOWNERS (SB-7), prompt changes (T3, separate).

### Evaluation

Next human PR uses the template. Revert condition: none plausible (docs-only).
