### Problem

Dead exports and unused deps accumulate invisibly — exactly the kind of rot a
code-factory multiplies. `knip` and `knip.jsonc` already exist in the repo but nothing
runs it, so its signal is wasted.

### Bet

If `yarn knip` becomes a CI check, dead code can't enter unnoticed, verifiable by CI
going red on a PR that adds an unused export.

### Success criteria

- [ ] `yarn knip` runs as a CI check on every PR (own job or step in `checks`).
- [ ] Current findings are NOT silenced with blanket ignores: each pre-existing finding is either fixed in this PR (if trivial, ≤ 10 lines total) or listed in the PR body as a proposed follow-up issue (title + one line each) for the operator to file.
- [ ] Any `knip.jsonc` ignore added is per-finding and commented with why.
- [ ] `.github/workflows/ci.yml` change is additive — existing jobs untouched.
- [ ] All of: `yarn lint`, `yarn check-types`, `yarn test:run` green in CI.

### Out of scope

Actually deleting non-trivial dead code (those become their own T1 issues), coverage (SB-3).

### Evaluation

knip check green on the next 5 loop PRs; follow-up issues filed by operator from the PR-body list. Revert condition: knip false-positives block 2+ unrelated PRs.
