### Problem

CI (Y0.4) runs tests but not coverage, so a PR can delete test value invisibly. The
loop is about to generate many PRs; without a ratchet, coverage decay compounds
silently. `@vitest/coverage-v8` is already a backend devDependency — only the gate is
missing.

### Bet

If we add a coverage job that fails when coverage drops below a committed baseline,
then any loop PR reducing coverage goes red, verifiable by pushing a scratch branch
deleting a test and watching CI fail.

### Success criteria

- [ ] `yarn test:coverage` runs in CI (job `coverage` or folded into `tests`) on every PR.
- [ ] A committed ratchet file (e.g. `apps/backend/coverage.thresholds.json`) pins thresholds to the CURRENT measured baseline − 0 (measure, then commit those numbers; do not invent targets).
- [ ] Vitest `coverage.thresholds` reads those values; a branch deleting `apps/backend/src/modules/teams/*.test.ts` assertions goes red (prove via local run output in the PR body, not a pushed scratch branch).
- [ ] `.github/workflows/ci.yml` change is additive — existing `checks`/`tests` jobs untouched.
- [ ] All of: `yarn lint`, `yarn check-types`, `yarn test:run` green in CI.

### Out of scope

Frontend coverage (no frontend unit tests yet), coverage % improvements, Playwright (SB-5), knip (SB-4).

### Evaluation

Next 5 loop PRs: coverage job visible and green on each. Revert condition: coverage job flakes on unchanged code twice — revert and refile with diagnosis.
