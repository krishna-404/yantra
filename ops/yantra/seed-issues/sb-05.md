### Problem

The frontend has a Playwright E2E suite (`apps/frontend/e2e/`, `test:e2e:with-build`
scripts) but CI never runs it, so frontend regressions ship invisibly. The B-group
strip work (SB-11/12) will touch frontend routes — it needs this net in place.

### Bet

If CI runs the E2E suite headless against a test-mode build, frontend breakage goes
red pre-merge, verifiable by the suite passing on main and failing on a deliberately
broken scratch run (shown locally in the PR body).

### Success criteria

- [ ] New CI job `e2e`: postgres service + backend test server + `yarn test:e2e:with-build` headless, using the existing `test:db:setup` → `test:server:start` pattern (see e2e/globalSetup.ts for what the suite expects).
- [ ] Flake policy: Playwright `retries: 1` in CI only; a test failing twice fails the job.
- [ ] On failure: Playwright HTML report + traces uploaded as an Actions artifact.
- [ ] Existing `checks`/`tests` jobs untouched; `e2e` NOT yet added to required checks (that's SB-7).
- [ ] All of: `yarn lint`, `yarn check-types`, `yarn test:run` green in CI.

### Out of scope

New E2E tests, making e2e a required check (SB-7), Flutter/device testing (Phase 4).

### Evaluation

e2e job green on 3 consecutive main runs before SB-7 makes it required. Revert condition: >1 flake-failure per day on unchanged code.
