### Problem

The database still carries OneQ tables (journal entries, prompts and their satellites)
with no remaining code references (#8–#13 removed them all). Per the repo's two-step
deletion standard (README "Deployment & Compatibility"), code stopped using the fields
first; this is the subsequent-release drop.

### Bet

If we add a migration dropping the OneQ tables, a fresh-DB migrate+seed+test cycle runs
green, verifiable by `yarn db up` + full suite in CI.

### Success criteria

- [ ] New auto-generated migration (`yarn db g <name>` — never hand-written SQL files) dropping the journal/prompt tables and their FKs/indexes. Enumerate the exact table list in the PR body from the live schema, don't guess.
- [ ] Migration has a down-path, or the PR body states "irreversible, because …" explicitly (rubric T2 extra check).
- [ ] Fresh DB: `yarn db create && yarn db up && yarn test:db:setup && yarn test:run` green (CI tests job proves this; paste local fresh-run tail in PR body too).
- [ ] Sync-infra tables (per D16) untouched — list them in the "not touched" PR-body section.
- [ ] All of: `yarn lint`, `yarn check-types`, `yarn test:run` green in CI.

### Out of scope

Seed/fixture cleanup (#15), any code change outside `apps/backend/src/db/migrations/` + generated artifacts.

### Evaluation
